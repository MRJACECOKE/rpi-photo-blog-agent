# 한계점 · 문제점 · 개선점

이 문서는 **자랑이 아니라 인수인계용 결함 목록**이다. 다음 담당자가 지뢰를 밟지 않도록 아는 것을 전부 적는다.
"아마 괜찮을 것"이라고 쓰지 않는다. 확인한 것과 확인하지 못한 것을 구분한다.

심각도: **H**(운영에 실제 영향) / **M**(조건부 영향) / **L**(개선 여지)

---

## 1. 하드웨어 · 성능

### H-1. 처리량이 컨텍스트 누적에 따라 계속 떨어진다

실측(job `20260817-e2e-kitchen`):

```
3.83 → 3.26 → 3.03 → 2.70 → 2.52 → 2.45 → 2.38 tok/s
```

KV 캐시가 커지며 attention 비용이 증가한다. 게이트(1.5 tok/s)는 통과하지만
**마지막 섹션 기준 여유는 약 1.6배**다. 벤치 수치(4.79 tok/s)만 보면 3.2배로 착각한다.

- **영향**: `config/blog.yaml:sections`를 늘리거나 `max_chars`를 올리면 게이트에 닿을 수 있다.
- **현재 대응**: `timeouts.llm_total_sec` 총 예산을 적용해 초과 시 남은 섹션을 중단하고
  `FAILED_RECOVERABLE`로 남긴다. 무한정 느려지게 두지 않는다.
- **개선안**: 섹션을 2~3개 그룹으로 나눠 그룹마다 서버를 재기동하면 KV 캐시가 초기화돼
  속도가 회복된다. 대신 그룹 경계에서 기저 프롬프트를 다시 프리필해야 하므로(약 190초)
  손익을 실측해서 결정해야 한다. **미검증.**

### H-2. NVMe가 없다 — cold load 137.8초

microSD 단독이다. 재부팅 직후 첫 실행은 10.1 GiB를 SD에서 읽느라 **137.8초**가 걸린다.
page cache가 살아 있으면 1.85초다.

- **영향**: 재부팅 후 첫 job만 느리다. 연속 실행에서는 문제없다.
- **개선안**: NVMe HAT 장착이 근본 해결책이다. 그 전까지는 부팅 후
  `cat models/llm/*.gguf > /dev/null`로 미리 캐시를 데워 두는 방법이 있다.
  단, 10 GiB를 page cache에 올리므로 다른 작업과 경합할 수 있다.

### M-3. 디스크 여유 22 GiB (81% 사용)

모델 추가 다운로드가 제약된다. VLM을 7B로 올리지 않은 이유 중 하나다.

- **현재 대응**: `pipeline.preflight()`가 여유 2 GiB 미만이면 `BLOCKED_EXTERNAL`로 멈추고
  정리 대상을 안내한다. **자동 삭제는 하지 않는다.**
- **개선안**: `work/` 캐시 정리 UI. 사용자가 선택해서 지우게 한다.

### M-4. 온도 정책이 실전에서 발동한 적이 없다

전 측정 구간 최고 68.8 °C, `throttled=0x0`이었다. 즉 **80 °C 대기 로직과 88 °C 중단 로직은
코드 경로가 실행된 적이 없다.** 단위 테스트로만 검증됐다.

- **영향**: 여름철 케이스 없는 환경에서 처음 발동할 때 예상과 다르게 동작할 수 있다.
- **개선안**: 임계값을 낮춰(예: 55 °C) 한 번 강제 발동시켜 경로를 확인할 것.

## 2. 모델 품질

### H-5. VLM(3B)의 관찰 품질이 낮다

Qwen2.5-VL-3B는 지시 준수력과 관찰 정밀도가 모두 약하다. 실측에서 관측된 것:

| 문제 | 예시 | 현재 대응 |
|---|---|---|
| 값이 영어로 출력 | `"U-shaped"`, `"marble"` | 필드별 한국어 열거값 명시 |
| 예시 JSON을 그대로 복사 | `"40자 이내 한국어 문장"`이 값으로 | 완성 예시 제거 + 파서가 지시문 복사 검사 |
| 색상어를 엉뚱한 필드에 | `hardware_visible: ["화이트", ...]` | `color_terms`로 색상만인 항목 제거 |
| `notable_points`가 문장이 아닌 명사구 | `"화이트 색상의 냉장고"` | **미해결** |
| 사진마다 거의 같은 관찰 반복 | `"화이트 색상의 X"` 7회 | 중복 제거만 함. 유사 문구는 남음 |

- **영향**: 근거 JSON의 정보 밀도가 낮아 본문이 피상적이 된다. 사실을 지어내지는 않지만
  **"깊이 있는 글"은 나오지 않는다.**
- **개선안 1**: Qwen2.5-VL-7B로 올린다. 단 1024 px에서 3B가 이미 227.9초였으므로
  7B는 180초 게이트를 넘길 가능성이 크다. 입력을 640 px로 더 낮춰야 할 수 있고, 그러면 관찰 정밀도가 다시 떨어진다.
  **디스크 5~6 GiB 추가 필요. 미검증.**
- **개선안 2**: 사진당 2회 호출(전체 구도 / 세부 하드웨어)로 나눠 관찰을 늘린다.
  시간이 2배가 되므로 사진 장수 상한을 낮춰야 한다.

### M-6. 같은 사진에서 layout 판정이 흔들린다

3장의 사진에서 `layout`이 일자형/ㄱ자형으로 갈렸고, 다수결로 하나를 골랐다.
사진 각도에 따라 실제로 달라 보이므로 모델만의 문제는 아니지만,
**다수결이 틀리면 본문 전체가 틀린 전제 위에 쓰인다.**

- **개선안**: 판정이 갈리면 `null`로 두고 본문에서 배치를 단정하지 않게 한다.
  현재는 다수결이라 소수 의견이 사라진다.

### M-7. 12개 섹션 구조가 짧은 입력에도 그대로 적용된다

사진 1장에 관찰이 빈약해도 섹션 12개를 채우려 한다. 분량 하한(1,800자)이 있어
**모델이 일반론으로 빈칸을 메우는 압력**이 생긴다.

- **현재 대응**: "일반적으로"를 명시하게 하고, 근거 없는 브랜드·가격·치수는 규칙으로 차단한다.
  거짓은 막지만 **밀도 낮은 문장은 막지 못한다.**
- **개선안**: 관찰 개수에 따라 섹션 수를 동적으로 줄이는 것. 예를 들어
  `notable_points` 총합이 N개 미만이면 선택 섹션을 건너뛴다.

## 3. 개인정보

### H-8. 문자 PII를 규칙으로 잡지 못한다

1차(규칙 기반) 검사가 잡는 것은 **얼굴·QR·바코드·GPS뿐**이다.
사진 속 전화번호, 주소, 명함, 계약서, 호수 표기는 **VLM 2차 검사에만 의존한다.**

- **영향**: VLM이 놓치면 그대로 통과한다. 3B 모델의 OCR 능력은 신뢰도가 높지 않다.
- **개선안**: OCR(예: PaddleOCR, tesseract-kor)을 1차에 추가하고
  전화번호/주소 정규식으로 판정한다. 사진당 처리 시간이 늘고 의존성이 커진다. **미구현.**

### M-9. 얼굴 검출 임계값이 단일 실측 사례에 기반한다

`face_confirm_score = 0.90`은 **오검출 1건(0.767)과 정검출 1건(0.91)**을 근거로 잡았다.
표본이 2개다.

- **영향**: 다른 종류의 오검출(예: 인형, 그림, 반사)이 0.90을 넘으면 잘못 보류된다.
  반대로 작게 찍힌 진짜 얼굴이 0.75 미만이면 놓친다.
- **개선안**: 실사용 사진 수십 장으로 점수 분포를 측정해 임계값을 재조정할 것.
  현재 값은 **잠정치**로 취급해야 한다.

### L-10. 보류 이미지는 사용자가 직접 가려야 한다

자동 블러/모자이크를 넣지 않았다. GUI가 "가림 처리 후 재업로드"를 안내만 한다.

- **개선안**: 검출된 bbox에 블러를 적용해 사용 가능하게 만드는 옵션.
  bbox는 이미 `privacy_flags.findings[].boxes`에 저장돼 있어 구현은 어렵지 않다.

## 4. 아키텍처 · 운영

### M-11. STAGE_4는 재개되지 않는다

섹션 8개까지 만들고 전원이 끊기면, 재실행 시 **12개를 처음부터 다시 만든다.**
draft는 `work/<job>/draft/`에 남아 있지만 재사용하지 않는다.

- **이유**: 생성 단계이고 재실행이 곧 "재생성"의 의미이며, GUI [재생성] 버튼이 같은 경로를 쓴다.
- **영향**: 20분짜리 작업이 중단되면 20분을 다시 쓴다.
- **개선안**: `--resume-sections` 플래그로 draft를 읽어 ChatML 기록을 복원하는 경로를 분리한다.
  다만 재생성 의미와 충돌하지 않게 명시적 플래그여야 한다.

### M-12. GUI 취소가 즉시 멈추지 않는다

취소 요청은 진행률 콜백 지점에서만 확인된다. 섹션 하나가 생성 중이면
**최대 그 섹션이 끝날 때까지(약 2~3분) 기다린다.**

- **개선안**: `LlamaServerRuntime.complete()`에 취소 토큰을 넘겨 HTTP 요청을 중단하고
  서버 슬롯을 비우는 경로 추가.

### M-13. 동시 실행 방지가 두 겹인데 층이 다르다

GUI는 자체 `threading.Lock`으로, 파이프라인은 `state/run.lock`(PID 파일)으로 막는다.
CLI와 GUI를 동시에 띄우면 **run.lock이 최종 방어선**이다.

- **확인된 동작**: CLI 실행 중 GUI `/api/system`이 `busy: true`, `runner: "cli"`를 보고한다.
- **미확인**: GUI에서 실행 중 CLI를 띄웠을 때의 사용자 경험. `LockError`가 나지만
  메시지가 친절한지 확인하지 않았다.

### L-14. Ollama 폴백 tier가 실전 검증되지 않았다

`config/models.yaml`에 ollama tier가 정의돼 있고 `OllamaRuntime`도 구현했지만,
**실제로 그 경로로 글을 만들어 본 적이 없다.** 상위 tier가 항상 성공했기 때문이다.

- **영향**: 진짜 폴백이 필요한 순간에 처음 실행되는 코드가 된다.
- **개선안**: 상위 tier를 일부러 막고(`is_available` 우회) 한 번 완주시켜 볼 것.

### L-15. `.meta.json`을 두 번 쓴다

품질 검사가 파일 배치 후에 실행되므로 `write_output()`을 두 번 호출한다.
첫 호출의 `quality`는 빈 객체다. 중간에 죽으면 불완전한 meta가 남는다.

- **개선안**: 품질 검사를 메모리 상태로 수행하고 파일은 한 번만 쓰거나,
  meta를 마지막에 한 번만 쓰도록 분리.

## 5. 검증되지 않은 것 (정직한 공백)

이 항목들은 **"안 된다"가 아니라 "확인하지 않았다"**는 뜻이다.

| 항목 | 상태 |
|---|---|
| HEIC 입력 | `pillow-heif`는 설치·로드 확인. **실제 HEIC 파일로 테스트하지 않음** |
| 사진 12장(상한) 처리 | 4장까지만 실행. 12장이면 VLM만 약 35분 |
| 온도 대기/중단 경로 | 단위 테스트만. 실제 발동 없음 |
| Ollama 폴백 tier | 미실행 |
| tier 자동 하향 경로 | 언로드 게이트가 항상 통과해 **하향 코드가 실행된 적 없음** |
| GUI 모바일 브라우저 | 반응형 CSS 작성했으나 실기기 확인 안 함 |
| systemd 서비스 | 유닛 파일만 작성. **활성화·재시작 동작 미확인** |
| 장시간 연속 운전 | 최대 40분 연속. 수 시간 운전 시 메모리 파편화·발열 미확인 |

## 6. 알려진 결함 (수정했지만 기록)

이미 고쳤으나, 같은 종류의 실수를 반복하지 않도록 남긴다.

| 결함 | 왜 위험했나 |
|---|---|
| `\b\d{3,4}\s*mm\b` 정규식 | 한글 뒤에서 `\b`가 성립하지 않아 **한국어 문장 속 치수 주장을 통째로 놓쳤다.** 영어 테스트만 했다면 영원히 못 찾았을 버그 |
| 얼굴 단일 임계값 | 멀쩡한 사진이 영구 제외되거나 진짜 얼굴을 놓치거나, 둘 중 하나를 선택해야 했다 |
| VLM 타임아웃 = 게이트 값(180초) | 실측 평균 167초라 여유가 13초. 사진 하나 때문에 분석을 통째로 잃을 뻔했다 |
| `abort_above_celsius` 등 미배선 | 설정 파일에 값이 있는데 코드가 하드코딩을 쓰고 있었다. **설정을 바꿔도 아무 일도 안 일어나는 상태** |
| GUI `busy` 판정 | GUI 자신의 실행만 봐서, CLI가 모델을 돌리는 중에도 "유휴"로 표시했다 |
| 거부된 섹션을 대화 기록에 남김 | 남겨 두면 다음 섹션이 금칙 표현을 따라 쓴다 |
| **문자 3-gram 자기중복률** | 한국어 조사·어미가 문자 반복을 지배해 **정상 글을 거부**했다. 결정적 증거: 사람이 직접 쓴 이 저장소 문서들이 0.200~0.338로 자기 기준을 통과 못 했다. 단어 3-gram으로 교체 |
| 섹션 지침 문구가 비문을 유도 | "확인되지 않은 항목은 '사진만으로는 확인되지 않습니다'로 처리"라고 쓰니 모델이 무관한 문장 끝에 접속어미로 붙였다. **지침 문구 자체가 결함**이었다 |

> **교훈.** 위 6건 중 3건(`mm` 정규식, 문자 3-gram, 지침 문구)은 **한국어 특유의 문제**였다.
> 영어 기준으로 만든 검사·지표·지침은 한국어에서 조용히 오작동한다.
> 새 검사를 추가할 때는 반드시 **사람이 쓴 한국어 텍스트로 먼저 교정(calibration)**할 것.

## 7. 우선순위 제안

다음 담당자가 시간이 한정돼 있다면 이 순서를 권한다.

1. **H-8 문자 PII OCR** — 개인정보 사고는 되돌릴 수 없다. 나머지는 품질 문제지만 이건 사고다.
2. **M-9 얼굴 임계값 재측정** — 표본 2개는 근거가 너무 얇다.
3. **H-5 VLM 업그레이드 검토** — 결과물 품질의 상한을 결정하는 요인이다.
4. **L-14 / tier 하향 경로 실행** — 진짜 필요할 때 처음 도는 코드를 남겨 두지 말 것.
5. **H-1 그룹 재기동 실측** — 섹션을 늘리려면 먼저 이것부터.
